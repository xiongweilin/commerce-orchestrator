# ADR-0010：验收门禁（故障注入 / 性能 / 生产提升条件）

- **Status**: Accepted
- **Date**: 2026-08-10
- **Superseded-by（生产提升条款）**: ADR-0015

## Context

系统承载对外效果与账务一致性，不能靠“看起来能跑”上线。需要可量化的自动化验收门禁，尤其验证幂等、恢复与对账语义。

## Decision

**自动化故障测试（门禁必过）**：

- **单 effect 重放 10 次**无重复副作用（幂等性验证）。
- **1000 次 kill injection 指标**：随机/定点杀死 worker 进程，验证恢复后无丢失、无重复副作用，指标达标。
- **重启恢复 ≤ 5 分钟**：从进程死亡到工作流可继续推进的时间预算。
- **30 天人审等待不占 worker**：长挂起不阻塞其他工作流执行。
- **对账差异一律进 `MANUAL_RECONCILIATION`**，**禁止自动抹平**；自动化断言任何自动抹平路径不存在。

**性能门禁**：

- 建立 p95/p99 响应与吞吐基准，配套压力测试；回归不达标不放行。

**首个生产提升条件（全部满足才可提升）**：

1. 首条纵向切片（21 步）端到端通过上述全部故障测试与对账演练；
2. 观察窗口内零未解差异（对账无残留）；
3. p95/p99 与压力测试达标；
4. 备份恢复与对账 runbook 演练完成（见 docs/runbooks/）；
5. 审批边界与四眼原则实现经合规/财务确认；
6. Odoo 19 External JSON-2 在真实 Community 容器实测通过（ADR-0008）。

## Consequences

**正面**：上线质量可量化；幂等/恢复/对账承诺有测试背书；生产事故面收窄。

**负面/约束**：门禁实现成本（注入工具、基准基线）；自动化设施需随功能演进维护；性能基准需定期校准。
