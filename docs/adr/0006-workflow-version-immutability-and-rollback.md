# ADR-0006：工作流版本不可变与回滚策略

- **Status**: Accepted
- **Date**: 2026-08-10

## Context

长流程运行中可能跨越多次部署；若原位修改已发布工作流的步骤顺序，运行中的流程与代码语义不一致，恢复后可能执行错误步骤。线上故障时需要可预演的降级/回滚路径。

## Decision

- **每个工作流类型带版本号（version）**；步骤顺序一经发布**不可原位修改**，新逻辑以新版本发布，旧版本继续运行。
- **旧版本由兼容 worker drain**：旧版本工作流由保留的旧 worker 继续处理至完成或按策略终止，不强行迁移到新代码。
- **回滚顺序固定**：
  1. 停止新命令入口（不再接受新工作流）；
  2. 保留旧版本 worker 继续运行；
  3. 撤销 connector 写权限（Shopify / Odoo adapter 进入只读/停写）；
  4. 业务补偿（人工处置、贷项通知单、库存调整等受控路径）。
- **审批决策必须携带 `expectedWorkflowVersion`**：与当前版本不匹配返回 `409 workflow_version_conflict`，防止过期决策作用于新版本。

## Consequences

**正面**：运行中工作流语义稳定；回滚有确定顺序，可演练；审批不可作用到错误的版本。

**负面/约束**：每个版本有生命周期成本（旧 worker 保留期）；版本数量需治理（超期版本强制终结）；回滚第 4 步通常需要人工介入。
